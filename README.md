# NIKKE RECRUIT LAB

『勝利の女神：NIKKE』の恒常SSRコレクション管理・募集期待値計算機です。HTML・CSS・JavaScriptだけで動き、`dist/`を静的サイトとして配信できます。

## 使い方

1. 顔アイコンの一覧で所持・凸状況とウィッシュリストを登録します。
2. 一般募集チケット、アクセス、モールドの所持数を入力して期待値を確認します。
3. 編集内容はその端末のブラウザへ自動保存されます。
4. 別の端末へ渡すときは「セーブ」を押します。データ入りURLを同じタブで開き直します。
5. 保存後のタブをブラウザの共有機能で送ります。端末内のデータと違う場合は取り込む内容を選べます。

## 主な機能

- 2026年10月28日を基準とする既存の恒常SSR124体、顔アイコン、明るい配色。
- 未所持・無凸・1～3凸・コア＋1～＋7の登録と絞り込み。
- 4グループのウィッシュリスト、計算対象の除外、手動キャラ追加。
- オーバースペックは所属企業とピルグリム・OSの両方で一覧を絞り込み。募集計算とウィッシュ枠はピルグリム・OS扱い。
- チケット・アクセス・モールド13項目と、還元による追加パーフェクトの計算。
- 重複を含むSSR期待数、重複を数えない新規種類数の期待値、新規を1体以上得る確率、キャラごとの確率。
- 端末内の自動保存、圧縮URLでの引き継ぎ、取り込み前の1世代復元、JSONとCSV出力。

既存の10月29日基準の127体切り替えも維持しています。顔画像を確認・同梱した対象は10月28日基準の124体です。追加キャラや手動追加キャラには名前による代替表示を使います。対象・確率はゲームから自動更新しません。

## 保存について

アプリ独自のログインやクラウドデータベースは使いません。実際の所持データはブラウザの`localStorage`とセーブしたURLで扱います。GitHubのコードへ実データを書き込む処理はありません。

共有URLはセーブ時点の状態です。受信側で編集したら、再度セーブしてURLを送り返してください。URLを知っている人は内容を復元できます。JSONバックアップや個人のデータ入りURLを公開リポジトリへ登録しないでください。

保存URLは`#`以降に含めます。形式のバージョンと保存日時を持ち、キャラの並び順によらない識別子で保存します。通常データはgzip圧縮を使用します。圧縮が使えないブラウザでは非圧縮で書き出し、対応範囲や長さを超える場合はJSONでの移行を案内します。URLデータは16,000文字、復元後データは250,000バイトまでというアプリ内の制限があります。

旧JSONの所持情報は互換性を保ち、凸がないキャラは無凸で取り込みます。サイトのURLが変わった際の初回移行にはJSONを使用してください。

## 計算の前提

独立した経路でキャラiを1体以上得る確率は「1 - 各経路で一度も得ない確率の積」です。最初に未所持だったキャラについてこの確率を合計し、新規獲得種類数の期待値を求めます。ウィッシュは計算中固定です。通常モールドのSSRは該当プール内で均等とし、OSはピルグリムのプールと共通です。

アクセスは50個未満のパーフェクト欠片の分布を逐次計算し、成功・失敗・失敗時の還元の関係を保持します。既存の欠片の端数と還元で追加できる確定募集も含め、二重計上を避けます。

計算中のウィッシュ入れ替え、ボーナス選択交換、ボディラベル交換、目標の凸に達する確率は計算対象に含めません。確率・対象の根拠と設定は画面から確認できます。

## GitHub Pagesで配信する

[導入手順](docs/GITHUB-SETUP.md)に沿って進めます。標準案はGitHub Freeの公開リポジトリ＋公開Pagesです。

`.github/workflows/pages.yml`は、`main`への反映または手動実行でテストを行い、成功後に`dist/`だけを配信します。Node.js 24を使用し、外部パッケージのインストールは不要です。GitHubの「Settings → Pages → Source」は「GitHub Actions」に設定します。

## 開発・確認

```sh
npm test
```

Node.jsの組み込みテスト機能を使います。募集計算・凸管理に加え、URLの圧縮と復元、壊れたデータ、長さ制限、旧形式、上書き前のバックアップ、保存失敗時の保全、アプリのイベント配線、124体の画像同梱を確認します。

イベント配線のテストはDOMの代用を使うため、ブラウザでの画面表示やタブ共有を検証するものではありません。実際のスマホとPCで、見た目と双方向の引き継ぎを確認します。
